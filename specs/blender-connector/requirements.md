# CONN-BLENDER-CONNECTOR — Requirements

Each row is one requirement. A row names the file it touches and the test that proves it. The generator sets each row's state in `status.json`.

| `CONN-BLENDER-CONNECTOR-R001` | **Declare the `mcp-for-blender` stdio upstream.** Subsystem: upstream declarations. `blender_connector/upstreams.py` holds the tuple `UPSTREAMS` of one `UpstreamDecl` value (`SCION-CONNECTOR-CONTROL-R914.1`). It has `name` and `namespace` `blender`, `kind` `stdio`, `command` `mcp-for-blender`, `args` empty and `env` empty, so no secret value ever appears in the declaration. `activation` is `active`: ten proxied tools carry no activation pressure, so the namespace is visible from the first list. `on_drift` is `warn`. The `sandbox` is an explicit empty grant: both root tuples are empty, which the SDK treats as an explicit deny, so no root flag is ever passed; the upstream carries no read or write root flags, and file access is governed inside Blender, not by CLI flags. The child environment is clean: only the setting `SCION_UPSTREAMS_INHERIT_ENV` names cross to the upstream process, and its shipped value `PATH,HOME,LANG,DISABLE_TELEMETRY,BLENDER_HOST,BLENDER_PORT,BLENDER_MCP_SAFE_MODE` carries the telemetry opt-out and the addon socket address. Knobs: `DISABLE_TELEMETRY` (start `1`), `BLENDER_HOST` and `BLENDER_PORT` (start `localhost` and `9876`). Refusals come from the SDK: `UPSTREAM_ROOTS_REQUIRED` when a stdio declaration carries no sandbox, `UPSTREAM_SPAWN_FAILED` when the binary is absent. Caller chain: `run` → `build_server` → `_attach_upstreams` (`scion_sdk/connector/_serve.py`) → `attach_upstreams`, which reads `connector.upstreams`; the `Connector` in `blender_connector/__init__.py` passes `upstreams=UPSTREAMS`. Shape: one module `blender_connector/upstreams.py` with the constants `UPSTREAM_NAME`, `BLENDER_COMMAND`, `INHERIT_ENV_SETTING` and `INHERIT_ENV_DEFAULT`, the socket-address configuration constants and the `build_upstreams()` function; the module is the package's declared configuration module, so the `blender_host()` and `blender_port()` accessors are the only environment reads in the package (the env-sprawl gate allows reads only there). Depends on: `SCION-CONNECTOR-CONTROL-R914.1`, `SCION-CONNECTOR-CONTROL-R914.2`, `SCION-CONNECTOR-CONTROL-R914.5`. | `tests/test_upstream_declarations.py::test_single_stdio_declaration`. One declaration exists with the pinned shape, an explicit empty sandbox grant and `activation` `active`. `tests/test_upstream_declarations.py::test_inherit_env_default_carries_telemetry_and_socket`. The shipped whitelist names the telemetry and socket variables. |
| `CONN-BLENDER-CONNECTOR-R002` | **Serve the full proxied surface; the initial list holds it all.** Subsystem: tool surface. The upstream starts `active`, so the first `tools/list` holds the four registry tools (`registry_list_namespaces`, `registry_activate`, `registry_deactivate`, `registry_status`), the one native tool `handshake`, and every proxied tool as `blender_<tool>` with the tag `ns:blender` and the `scion/upstream` metadata. Against a three-tool fixture upstream the count is eight; against the live snapshot surface of ten tools it is fifteen. The upstream's own resources, including its `ui://` viewport resource, pass through unmodified. The namespace `blender` owns the `blender_` prefix: a local tool with that prefix is refused at build time with `UPSTREAM_TOOL_COLLISION`. Caller chain: a client's `tools/list` → the aggregate provider → the `NamespaceTag` and `ActivationGate` of the loader (`scion_sdk/mcp/upstreams/loader.py`). Shape: no connector code; the tests pin the counts so a new tool is a visible change. Depends on: `CONN-BLENDER-CONNECTOR-R001`, `SCION-CONNECTOR-CONTROL-R914.5`. | `tests/test_tool_budget.py::test_initial_list_is_full_surface`. The first list holds exactly eight tools against the fixture upstream, and `registry_status` reports the upstream `ready` with the fixture tool count. |
| `CONN-BLENDER-CONNECTOR-R003` | **Probe the upstream for MCP support.** Subsystem: upstream discovery. The console script `blender-connector-probe` (`blender_connector/probe.py`) starts `mcp-for-blender` exactly as the registry would, with telemetry off, performs the MCP handshake and a `tools/list` with the SDK client, and prints one JSON result to stderr — stdout stays clean for the stdio transport, and the exit code is the machine signal: `{upstream, exposes_mcp, version, tool_count}`. A missing binary reports `BLENDER_MCP_NOT_FOUND`; a binary that does not complete the handshake reports `BLENDER_MCP_NO_MCP`. The script writes no file and exits non-zero when the upstream no longer answers. The operator or a host job runs it after each upstream update; it is the drift watchdog at the outbound boundary. Knob: `--timeout` 30 seconds (range 5 to 120). Caller chain: operator runs `blender-connector-probe` → `main` → `probe_upstream` → the SDK MCP client over stdio. Shape: one module `blender_connector/probe.py`; it reuses the SDK client and the declared command constant. Depends on: `CONN-BLENDER-CONNECTOR-R001`. | `tests/test_probe.py::test_probe_reports_the_fixture_upstream`. A fixture upstream reports `exposes_mcp` true with its version and tool count. `tests/test_probe.py::test_probe_reports_a_missing_binary`. An empty `PATH` reports `BLENDER_MCP_NOT_FOUND`. `tests/test_probe.py::test_probe_reports_a_dead_upstream`. A dying fixture reports `BLENDER_MCP_NO_MCP`. |
| `CONN-BLENDER-CONNECTOR-R004` | **Behavior: an absent upstream degrades, the server stays up.** Subsystem: deployment modes. The default mode runs `mcp-for-blender` from the process `PATH` as a pooled stdio child (`SCION-CONNECTOR-CONTROL-R914.8`). A binary missing from `PATH` marks only the `blender` upstream `unavailable` with the status code `UPSTREAM_SPAWN_FAILED`. The proxied tools are hidden, but the registry tools, the native tool and the packaged content keep serving. When the binary exists but the Blender addon socket is down, the upstream itself returns its actionable timeout text for each `blender_*` call; the connector never opens a second socket to Blender and never crashes. Caller chain: `registry_status` → the health report of the SDK (`scion_sdk/mcp/upstreams/health.py`), which records the spawn failure. Shape: no connector code; the SDK reports the refusal and the test pins it. Refusal code: `UPSTREAM_SPAWN_FAILED` from the SDK. Knobs: none. Depends on: `CONN-BLENDER-CONNECTOR-R001`, `SCION-CONNECTOR-CONTROL-R914.8`. | `tests/test_local_mode.py::test_missing_binary_marks_upstream_unavailable`. With the command absent from `PATH`, `registry_status` shows `unavailable` with `UPSTREAM_SPAWN_FAILED`, no `blender_*` tool is listed, `handshake` still answers with `command_found` false, and the content keeps serving. |
| `CONN-BLENDER-CONNECTOR-R005` | **Behavior: an operator overlay switches the upstream to a remote endpoint.** Subsystem: deployment modes. The remote topology is operator-supplied; the repository ships no host name. Refusals come from the SDK: a literal credential in the overlay refuses the merge with `UPSTREAM_DECL_INVALID`, and an unsafe URL refuses with `UPSTREAM_EGRESS_REFUSED`. Caller chain: `attach_upstreams` → `merge_overlay` (`scion_sdk/mcp/upstreams/overlay.py`) → the http transport factory. Shape: the example file and one test; no connector code. Depends on: `SCION-CONNECTOR-CONTROL-R914.3`, `SCION-CONNECTOR-CONTROL-R914.6`. | `tests/test_remote_overlay.py::test_example_overlay_switches_to_http`. | `CONN-BLENDER-CONNECTOR-R006` | **A connector-native readiness tool.** Subsystem: native tools. `blender_connector/mcp/` registers the tool `handshake` through `register_blender_tools`, toggled by the environment variable `BLENDERTOOL` (default on). It is a local diagnostic: it reports whether `mcp-for-blender` is on the `PATH` and whether the addon socket (`BLENDER_HOST`/`BLENDER_PORT`, default `localhost:9876`) answers a bounded TCP probe. It performs no Blender protocol traffic and opens no persistent connection. It is read-only and idempotent by its annotations. It carries no `blender_` prefix because the namespace owns that prefix (`UPSTREAM_TOOL_COLLISION`, `CONN-BLENDER-CONNECTOR-R002`). Caller chain: `build_server` (`blender_connector/mcp_server.py`) → `register_blender_tools` (`blender_connector/mcp/__init__.py`) → the tool function. Shape: one module with one tool and a bounded probe helper. Refusal: none; the output is a typed dict `{command_found, socket_open, host, port}`. Depends on: `CONN-BLENDER-CONNECTOR-R001`. | `tests/test_phase1_gate.py::test_phase1_gate` calls `handshake` with the fixture on `PATH` and expects `command_found` true. `tests/test_local_mode.py::test_missing_binary_marks_upstream_unavailable` calls it with an empty `PATH` and expects `command_found` false. |

Refusal code: `UPSTREAM_DRIFT_REFUSED` from the SDK, only under `refuse`. Depends on: `CONN-BLENDER-CONNECTOR-R001`, `SCION-CONNECTOR-CONTROL-R914.11`. | `tests/test_drift.py::test_drifted_upstream_reports_drifted`.
